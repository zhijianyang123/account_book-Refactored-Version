本文档面向 AI 编程助手，基于用户实测反馈，要求对现有 Flutter 记账本 App 进行优化和修复。请严格按以下要求修改代码。

一、设计风格全面转向
1.1 取消液态玻璃效果
彻底移除 liquid_glass_widgets 依赖及相关代码。

所有使用 GlassScaffold、GlassCard、GlassButton、GlassIconButton、GlassTabBar 的组件全部替换为原生 Flutter 组件。

不再使用任何苹果风格（Cupertino）组件，改为 Material 3 风格。

1.2 采用华为沉浸光感动效设计语言
参考华为官方文档：沉浸光感

核心理念：通过材质、光影、动效的结合，建立清晰的视觉层次，让界面呈现通透、精致的质感。

材质规范：

材质样式	透明度	适用场景
超薄（ULTRA_THIN）	极高透明	浮动工具栏
薄（THIN）	较强透明	搜索框
常规（REGULAR）	常规	通用场景
厚（THICK）	较强模糊	菜单
超厚（ULTRA_THICK）	极强模糊	弹窗
动效规范：

光随指动：用户触摸或滑动时，组件表面有光线跟随移动

光线勾勒：弹出组件时，边缘有流光勾勒轮廓

非线性形变：组件弹出时带有轻微的形变效果，打破生硬的规整边界

轻量变化原则：动效只做 scale、opacity、translate 的轻量变化，不建议大面积实时 blur 动画（会严重消耗性能）

设计优先级：

首页/明细页：高优先级，增加视觉层次，用阴影和 Z 轴深度区分模块，卡片之间形成“悬浮感”

统计页：中高优先级，图表和卡片用不同背景色和阴影区分信息层级

设置页：低到中优先级，以清晰稳定为主，不宜过度动效

Flutter 实现方式：

使用 Material 3 主题，通过 ColorScheme 定义色彩体系

卡片使用 Card 组件配合 elevation 和 shadowColor 实现悬浮感

弹出组件使用 showModalBottomSheet 或 showDialog 配合 AnimatedBuilder 实现形变和流光

页面过渡使用 PageRouteBuilder 配合 FadeTransition + SlideTransition + ScaleTransition

列表项点击使用 InkWell 的水波纹效果

二、性能优化（问题1：切换界面掉帧）
要求：必须彻底修复，这是最高优先级。

2.1 根因排查方向
检查 Provider 的使用方式：确保没有在顶层 build 方法中直接 watch 整个 Provider，导致任何数据变化都触发全局重建。

检查列表渲染：确认 ListView.builder 的 itemBuilder 中没有耗时操作（如数据库查询、复杂计算）。

检查动画：确认没有在 build 方法中创建动画控制器，没有使用不必要的 AnimatedContainer。

2.2 优化方案
方案一：使用 Selector 精准重建

将 Consumer 替换为 Selector，只在依赖的数据片段变化时才重建组件：

明细页的月份概览卡片：只监听 TransactionProvider 中的月度汇总数据

统计页的饼图：只监听支出分类数据

我的页的顶部卡片：只监听本月汇总和账户总资产

方案二：使用 const 构造函数

所有不依赖状态的静态 Widget 全部使用 const 构造函数，避免父组件更新时的不必要重建。

方案三：使用 keframe 分帧渲染（页面切换卡顿修复）

添加 keframe 包，对复杂页面进行分帧渲染。将页面拆分为多个 FrameSeparateWidget，首帧只渲染占位符，后续帧逐步渲染各模块。实测可将页面切换峰值帧时间从 112.5ms 降低到 30.2ms。

方案四：列表性能优化

明细页的日期分组使用 SliverList 替代嵌套 Column + ListView

为列表项设置 itemExtent 或 prototypeItem，减少布局计算

移除列表项中的 IntrinsicHeight、IntrinsicWidth 等昂贵布局

方案五：避免不必要的重建

将明细页的月份切换逻辑改为 ValueNotifier + ValueListenableBuilder，只重建月份显示部分

统计页的图表数据计算使用 compute 放到 isolate 中执行（如果计算量大）

方案六：Impeller 渲染引擎

确保在 Android 上启用 Impeller 渲染引擎（Flutter 3.x 默认启用），它能预编译着色器，显著降低首次渲染和动画切换时的卡顿。

2.3 验证标准
三个 Tab 之间切换无明显掉帧（目测流畅，无卡顿感）

明细页滚动流畅

进入记一笔页面和返回时无卡顿

九、搜索和筛选文字重叠修复（问题10）
要求：搜索和筛选页面出现文字重叠，必须修复。

9.1 问题原因
搜索框高度小于 48px 时，TextField 的文字基线对齐异常，导致文字偏上或与图标重叠

筛选面板中 Row 布局的 Text 组件没有设置 flex 或 Expanded，导致文字溢出重叠

9.2 修复方案
搜索框修复：

为 TextField 的 InputDecoration 设置 isDense: true，让输入框在紧凑高度下仍能正确居中文字

设置 contentPadding 合理值，避免图标和文字间距过小

搜索框高度建议不低于 44px

筛选面板修复：

所有水平排列的筛选项使用 Row + Expanded 包裹文字，或使用 Wrap 替代 Row

为 Text 组件设置 overflow: TextOverflow.ellipsis 或 softWrap: true

筛选标签使用 Chip 或 FilterChip 组件，自带合理的内边距和文字处理

检查 ListView 或 Column 中的 Text 是否设置了 maxLines 和 overflow
